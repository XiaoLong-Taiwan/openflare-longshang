# 儀表板統計口徑

儀表板 `/` 使用 `/api/v1/d/dashboard/overview`。時間範圍固定為資料產生時間往前 24 小時，`traffic.window_started_at` 與 `window_ended_at` 使用帶時區的時間字串；畫面依瀏覽器時區顯示。概覽保留既有 30 秒快取，因此重新整理不代表一定重新查詢資料庫。

## 流量與明細

- 請求、訪客、HTTP 狀態碼、網域及來源國家以保留的存取明細計算，`source` 為 `retained_access_logs`。受每日明細抽樣上限、保留期限及上報延遲影響，不能視為未抽樣的全部業務量，也不混入長期每日摘要。
- `error_count` 代表 5xx。`status_4xx_rate` 與 `status_5xx_rate` 為各類狀態碼請求數除以全部請求數，再乘 100；沒有請求時為 0。
- `average_qps` 為請求數除以 86400，既有 `estimated_qps` 保留並回傳相同數值。這是 24 小時平均值，不能用於判斷即時尖峰。
- 全窗口獨立訪客直接去重，不累加小時 UV。若摘要查詢失敗，`summary_fallback=true`，以小時趨勢重算請求、5xx 與 QPS；UV 與流量上報節點數無法確認，既有數值欄位維持 0，畫面明示不可用，不虛構節點數。

## 趨勢時間邊界

小時桶從 24 小時前所在整點到現在所在整點，共 25 個時間點；流量桶查詢仍限定精確起訖，因此首尾可能只有部分小時。請求與傳輸位元組趨勢使用同一窗口，避免漏掉起點部分小時或把窗口外整小時匯總混入。容量與磁碟趨勢使用相同時間軸；小時資源彙總代表整小時的讀數，原始容量快照回退則只接受窗口內樣本。

## 容量、覆蓋與新鮮度

容量卡使用每個已註冊節點最近 24 小時內的最新快照，與心跳／WebSocket 在線判定分開。CPU 的有效 0% 與總記憶體大於 0 時的 0% 都納入平均，沒有快照的節點不當成 0% 樣本。

`capacity.reported_nodes` 是有快照的節點數，分母為全部已註冊節點，包含 Edge、Relay 與 Tunnel。`fresh_nodes` 為快照距資料產生時間不超過 `freshness_threshold_seconds`（120 秒）的節點；`stale_nodes` 為超過門檻或時間在未來的快照；`missing_nodes` 為最近 24 小時沒有快照。`latest_snapshot_at` 為這些已註冊節點中最新快照時間，沒有樣本時為 null。過期樣本仍參與容量平均，應結合新鮮度判讀。

## 相容性與驗證

只在既有 `traffic`、`capacity` 物件增加欄位；節點仍為 17 欄，流量趨勢仍為 7 欄，其餘趨勢仍為 4 欄，索引順序不變。前端同時接受物件及壓縮陣列，舊 API 缺少新欄位時顯示「暫無資料」，不推測監測覆蓋或狀態碼比例。四語文案維護於 `frontend/messages/fragments/ops.*.json`。

回歸驗證包含 CPU／記憶體零值、空流量、fallback QPS 與 UV 不累加、新鮮度門檻、首尾部分小時、窗口外資料、壓縮欄位及舊 API 呈現。本次沒有資料表、Migration、節點上報協定或版本號變更。
